# Project Instructions

Project Intelligence Platform: multi-tenant, event-driven project knowledge platform. TypeScript pnpm
monorepo: `apps/web` (Next.js), `apps/api` (Fastify), `apps/worker` (BullMQ), `apps/mcp` (MCP server),
`packages/contracts` (shared schemas), `packages/domain` (pure rules), `packages/db`. PostgreSQL is the source of truth; Redis only for queues.

## Task Workflow

Tasks are managed in `docs/tasks/` (backlog/ → active/ → done/; the folder is the state).

1. `/task-start T-nnn` — moves it to `active/`, loads only what the task cites.
2. Implement, run relevant tests/checks (`make lint`, `make test`, `make test-integration`).
3. `/task-close` — verifies Acceptance, runs checks and `python3 tools/trace.py --write`, moves it to `done/`.

### Context Rules

- Do not read the entire backlog unless asked. The task file is the task context.
- Do not duplicate source code in docs. Inspect the code before assuming.

## Documentation

- `docs/PROJECT.md` — stable context. `docs/ARCHITECTURE.md` — architecture and decisions.
- `docs/GLOSSARY.md` — domain terms; use its spelling in code, UI and docs.
- `docs/tasks/README.md` — phase index. `docs/fsd/traceability.md` — generated by `tools/trace.py`.
- `docs/RELEASE.md` — release, rollback, hotfix.
- `docs/PIP-dev-spec.md` — requirements (FR/NFR/BR/AC); read only the section a task cites.
- `docs/fsd/open-questions.md` (OQ-nnn), `docs/fsd/decisions.md` (D-nnn), `docs/fsd/adr/`.
- `docs/fsd/*-contract.md` — versioned contracts (event envelope, REST API, MCP tools, adapter contract).
- `docs/source/requirements.md` — original product spec, untouched.

## General

- Smallest appropriate change. Follow existing conventions. No unrequested refactors.
- Every query and job runs in an organization scope; never bypass tenant checks (see ARCHITECTURE.md).
- Ordinary sync paths make no LLM calls. AI output is stored as derived, never over authoritative records.

## Git

- Commits, pushes, tags, merges and PRs are the user's: suggest them, do not run them.
- Ask before changing GitHub settings (Actions, branch protection / rulesets, merge options).
- graphify's git hooks are part of setup; leave them in place.

## Attribution

- No AI attribution anywhere: commits, PRs, issues, review comments, tags, changelog.
- No `Co-Authored-By: Claude …` trailer, no `Claude-Session:` link, no "Generated with Claude Code" footer.

## Versioning and Changelog

- One version, tag `vX.Y.Z`. Bump = `version` in `package.json`, `apps/web/package.json`,
  `apps/api/package.json`, `apps/worker/package.json`, `apps/mcp/package.json`,
  `packages/contracts/package.json`, `packages/domain/package.json`, `packages/db/package.json`,
  `tools/github_mock/package.json` → CHANGELOG entry in the same PR → tag after merge.
- Entry: `## [X.Y.Z] — YYYY-MM-DD`, sections Added · Changed · Fixed · Removed · Deployment, task numbers in brackets, compare link at the bottom.

## Codebase Navigation

- Prefer Graphify to locate related files, symbols and dependencies; plain search when the location is known.
- Do not read graphify-out/ directly; hooks keep it in sync. If stale, fall back to normal search.
